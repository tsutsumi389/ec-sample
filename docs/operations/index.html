この文書の位置づけ

本書は 現在この EC を運用するとしたら、人間が実際にどう手を動かすことになるか を、実装から読み取って書き起こしたものである。理想の運用手順でも、改善提案でもない。

本書に書くこと

管理画面の各操作の手順、入力項目の意味、押した結果として店頭・在庫・注文がどう変わるか。そして 画面が用意されていない作業（＝現状は DB を直接触るか、API を直接叩くしかない作業）。

本書に書かないこと

設計の改善案、機能追加の提案、自動化の設計。実装を変えるべきかどうかの判断は本書の外で行う。本書は「今こうなっている」だけを固定するためにある。

したがって本書には、直感に反する挙動や、明らかに不便な制約がそのまま記述されている。それらは誤記ではなく現状である。運用の設計を変えるときは、まずこの記録を出発点にすること。

目次

01運用の全体像登場人物と権限、管理画面 7 つの地図、全画面に共通する作法、できること・できないことの総覧。 02商品ライフサイクル商品を登録して公開し、情報を直し、売るのをやめるまで。6 つの販売状態、登録フォーム 11 項目、削除＝アーカイブの正体、カテゴリ管理。 03在庫と価格在庫数を直す唯一の経路、欠品したときに起きること、セール価格の入れ方と終わらせ方。期間指定も履歴も無い前提での回し方。 04受注〜出荷〜完了注文が入ってから配達完了まで、プルダウンを進めるだけの運用。キャンセルの経路が 2 つあり、在庫が戻るのは片方だけという分岐。 05クーポン運用クーポンの発行・配布・停止・失効。割引額の計算規則と、使用回数を制限できないことから来る運用上の制約。 06A/Bテスト運用実験の企画から開始・監視・判定・終了まで。実際に画面が変わる 2 つの実験キー、結果画面の読む順序、やってはいけない操作。 07カタログ品質と顧客接点検索・レコメンドの土台になる埋め込みの更新、レビューと商品 Q&A の扱い、AI アシスタントの会話、ユーザー管理。 08画面が無い作業と落とし穴DB シェルと API 直叩きでしかできない作業の手順、そして全章の警告を 1 枚にまとめた罠の一覧。
