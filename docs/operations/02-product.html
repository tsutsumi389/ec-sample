02商品ライフサイクル

商品を登録し、公開し、情報を直し、売るのをやめるまで。すべて /admin/products の一画面と、そこから開くモーダル 1 つで行う。

2.16 つの販売状態

商品の見え方・買えるかどうかは、すべて「販売状態」1 項目から決まる。「公開フラグ」「在庫切れフラグ」のような個別のスイッチは存在しない。

draft
下書き。作りかけの商品を置いておく状態。新規登録の初期値。
一覧に出るページが開く買える
coming_soon
近日発売。棚には並べて見せるが、まだ買わせない。店頭には「近日発売」と出る。
一覧に出るページが開く買える
on_sale
公開中。買える唯一の状態。ただし在庫が 0 ならボタンは「在庫切れ」になる。
一覧に出るページが開く買える
suspended
一時停止。棚には残したまま販売だけ止める。店頭には「販売停止中」と出て、図版が沈む。
一覧に出るページが開く買える
discontinued
販売終了。一覧・検索から消えるが、URL を直接開けば見える（既存のリンクやブックマークを死なせないため）。
一覧に出るページが開く買える
archived
アーカイブ。店頭から完全に消える。管理画面の「削除」ボタンが実際に行うのはこれ。
一覧に出るページが開く買える
遷移の制約は無い

どの状態からどの状態へでも移せる。archived から on_sale へ一足飛びに戻すこともできる（ただしフォームから archived は選べない。2.6 を参照）。順序を守らせる仕組みは無いので、正しい順序は運用側で担保する。

2.2商品を登録して公開する

  1. /admin/products を開き、右上の「新規作成」を押す
  2. モーダルに入力する。必須は 商品名・価格・在庫数・販売状態 の 4 つだけで、他はすべて任意（項目の詳細は 2.3）
  3. 販売状態は 「下書き」のまま保存する。ここで「公開中」を選ぶと、保存した瞬間に店頭の一覧へ並び、購入もできてしまう
  4. 「保存する」を押す。エラーがあればモーダル内に赤字で出て、モーダルは閉じない（入力は失われない）
  5. 一覧に行が増えたことを確認する。並び順は登録順なので、新しい商品は一覧のいちばん下に付く
  6. 内容を確認したら「編集」を開き、販売状態を「公開中」（または「近日発売」）に変えて保存する。これが公開の操作にあたる
  7. 店頭（http://localhost:3000/products）に並んだことを目視で確認する
商品コード（SKU）が重複すると原因の分からないエラーになる

SKU は全商品で一意でなければならないが、重複を事前に知らせる仕組みが無い。既にある SKU を入力して保存すると、画面には「サーバーエラーが発生しました。しばらくしてから再度お試しください。」としか出ず、SKU が原因だとは分からない。
加えて SKU は前後の空白が取り除かれないため、ABC と ABC （末尾に空白）は別の商品コードとして両方登録できてしまう。採番は手作業なので、登録前に一覧で重複を確認すること。

2.3登録・編集フォームの項目

新規作成と編集は同じモーダルを使う。項目別の個別編集画面は無い。

項目必須入力方法と注意
商品名必須自由入力。文字数の制限は無い。空白だけでも通ってしまうので注意
商品コード（SKU）任意自由入力・自動採番なし。全商品で一意。空にすると未設定になる。重複と前後の空白に注意（2.2 の警告）
説明任意複数行のテキスト。店頭の商品ページに出るほか、検索用のベクトルにも取り込まれるので、素材や用途を書くと検索に乗りやすくなる
カテゴリ任意既存カテゴリから選ぶ。「未分類」を選ぶと所属なし。このモーダルからカテゴリは作れないので、先にカテゴリ管理で作っておく
価格（円）必須整数・0 以上。定価にあたる
在庫数必須整数・0 以上。増減ではなく絶対値の上書き（詳細は 03 章）
セール価格（円）任意入れるとこちらが実売価格になる。空にすると定価に戻る。定価より高い額も 0 円も入力できてしまう（03 章の警告）
販売状態必須下書き / 近日発売 / 公開中 / 一時停止 / 販売終了 の 5 択。アーカイブはここから選べない
メイン画像URL任意URL の手入力のみ。アップロード機能は無い。同梱の絵を使うなら /products/<名前>.svg の形。一覧のサムネイルに使われるのはこの 1 枚だけ
追加画像URL任意1 つのテキスト欄に 1 行 1 URL で並べる。表示順は行の順。空行は無視される。並べ替えは行を書き直す以外にない
仕様任意「仕様を追加」で行が増え、各行に 項目名 / 値 を入れる（例: 重量 / 約 350g）。行の削除はできるが並べ替えはできない。どちらかが空の行は保存時に捨てられる
仕様欄に在庫・価格・販売状態を書かない

仕様は「モノの事実」（サイズ・重量・素材・保証など）だけを書く欄である。在庫や価格は状態であって仕様ではなく、ここに書くと商品ページに同じ数字が二度並ぶ。項目名はカテゴリを跨いで使い回すこと（重量・素材・本体サイズ・保証期間 など）。値は単位まで含んだ表示用の文字列でよい。

画像 URL は間違えても保存できてしまう

URL の形式チェックも到達確認も無い。打ち間違えた画像は店頭で「画像なし」のプレースホルダに差し替わって表示されるだけで、管理画面には何のエラーも出ない。保存後に店頭の商品ページを開いて絵が出ているか目視すること。

2.4商品情報を直す

  1. 一覧の「編集」を押すと、現在の値が入った状態でモーダルが開く
  2. 直したい項目だけ書き換えて「保存する」を押す
  3. 保存の裏で、その商品 1 件の検索用ベクトルが自動的に貼り直される（07 章）。成功したかどうかは画面に出ない
画像と仕様は「差分更新」ではなく「まるごと置き換え」

保存を押すと、フォームに表示されている画像 URL と仕様の内容がそのまま既存の内容を置き換える。追加画像欄の行をうっかり消したまま保存すれば、その商品のギャラリーは消える。編集前の状態を控えておく仕組みは無い（変更履歴が残らないため復元もできない）。

2.5売るのをやめる

「やめ方」は 3 段階あり、どこまで消したいかで選ぶ。

やりたいこと操作結果
一時的に売るのを止める
（入荷待ち・調査中など）		 編集 → 販売状態を「一時停止」 棚には残る。商品ページも開く。購入パネルの代わりに「販売停止中」と、カテゴリの棚へ戻る導線が出る
取り扱いを終える
（後継品に入れ替えるなど）		 編集 → 販売状態を「販売終了」 一覧・検索から消える。URL を知っている人はページを開けるので、過去の購入者やブックマークからは引き続き見える
棚から完全に下げる 一覧の「削除」ボタン アーカイブ状態になる。店頭からは完全に消える（一覧にも出ず、ページも開かない）。管理画面の一覧からは消えない

2.6「削除」ボタンの正体と、アーカイブからの復活

商品は決して物理削除されない。過去の注文明細が注文時点の商品名と価格を保持しているとはいえ、商品そのものが消えると履歴の追跡ができなくなるためである。

  1. 一覧の「削除」を押すと、ブラウザの確認ダイアログに「『商品名』を削除しますか？」と出る
  2. OK を押すと、その商品の販売状態が アーカイブに変わるだけで、行は一覧に残り続ける（状態バッジが「アーカイブ」になる）
  3. 店頭からは完全に消える。一覧にも検索にも出ず、商品ページも開けなくなる
確認ダイアログの文言が実際の挙動と食い違っている

ダイアログは「削除しますか？」としか言わないが、実際に起きるのはアーカイブである。行が消えないことに驚いて何度も押さないこと（何度押しても同じ結果になるだけで害は無い）。商品を管理画面の一覧から本当に消す手段は存在しない。商品数が増えるほど、アーカイブ済みの行が一覧に溜まっていく。

アーカイブから戻す

  1. 一覧でアーカイブ状態の行を見つけ、「編集」を押す
  2. モーダルの販売状態は 自動的に「下書き」に置き換わっている（アーカイブが選択肢に無いため）
  3. そのまま「保存する」を押すと、商品は下書きに戻る。これが唯一の復活手段である
  4. 再び売るなら、続けて販売状態を「公開中」に変えて保存する
裏返すと

アーカイブ済みの商品を「中身を確認するだけ」のつもりで編集モーダルから保存すると、意図せずアーカイブが解除されて下書きに戻る。見るだけならモーダルは「キャンセル」で閉じること。

2.7カテゴリを管理する

/admin/categories。入力項目は カテゴリ名 と スラッグ の 2 つで、どちらも必須。

  1. 「新規作成」でモーダルを開き、カテゴリ名（例: キッチン家電）とスラッグ（例: kitchen）を入れて保存する
  2. スラッグが既存と重複すると「このスラッグは既に使用されています。」と出る。カテゴリ名の重複は素通しになるので、同名カテゴリを作らないよう一覧で確認する
  3. 作成・改名・削除のあと、商品フォームのカテゴリ選択肢は自動で更新される。ただし別タブで開きっぱなしの管理画面には反映されないので、そちらは再読み込みする
スラッグは入力を求められるが、現在どこにも使われていない

店頭のカテゴリページの URL は ID を使う（/categories/3 のような形）ため、スラッグは管理画面の一覧に表示されるだけである。形式チェックも無く、日本語や空白を含む値も登録できる。将来使われる可能性を考えると、英小文字とハイフンで揃えておくのが無難。

カテゴリの削除は取り消せず、影響件数も表示されない

カテゴリは商品と違って本当に削除される。所属していた商品は消えず「未分類」に落ちるが、その商品はカテゴリの棚から辿れなくなり、商品ページのパンくずからもカテゴリが消える。確認ダイアログは「該当商品のカテゴリ設定は解除されます」と言うだけで、何件が未分類になるかは表示されない。削除前に、そのカテゴリに何が属しているかを店頭のカテゴリページで確認すること。
さらに、未分類に落ちた商品の検索用ベクトルは古いカテゴリ名を含んだまま残る（カテゴリ削除では貼り直されない）。気になる場合は該当商品を開いて保存し直すか、全件の再構築を行う（07 章）。
