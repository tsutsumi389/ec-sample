06A/Bテスト運用

/admin/experiments で実験を作り、開始し、結果を読んで終わらせる。作成後に内容を直す画面が無いため、作る前にどこまで決めておくかがこの運用の要になる。

6.1いま実際に試せること

画面が変わる実験キーは 2 つだけ

管理画面から実験はいくつでも作れるが、店頭の見た目が実際に変わるのは、フロントがそのキーを読んでいる場合だけである。現在読まれているのは次の 2 つのキーのみ。これ以外の名前で実験を作っても、割り当てと計測は動くが画面は何も変わらない（＝ A も B も同じ画面を見る意味のない実験になる）。

実験キー変わるもの枝の設定値（config）の書き方
pdp_section_order 商品ページ下部のセクションの並び順 {"sections": ["reviews", "qa", "recommendations", "related", "recently"]}
使えるキーは recommendations（おすすめ）/ related（関連商品）/ reviews（レビュー）/ qa（商品 Q&A）/ recently（最近見た商品）。知らない名前は黙って無視されるため、打ち間違えても画面は壊れない（そのセクションが消えるだけ）
pdp_cta_copy カートに追加ボタンの文言（PC の購入パネルとスマホの固定バーの両方） {"label": "いますぐカートに入れる"}
省略すると既定の「カートに追加」になる
最初から 2 件入っている

初期データとして pdp_section_order が配信中（おすすめ先行 vs レビュー・Q&A 先行、50:50）、pdp_cta_copy が下書き（「開始する」を押す流れを試せるように）で登録されている。まずはこの 2 件で操作を確認するとよい。

6.2実験の 4 つの状態

draft
下書き。作成直後は必ずこの状態。まだ誰にも配信されていない。
配信中枝を編集できる削除できる
running
配信中。訪問者に枝が割り当てられ、曝露と成果が記録される。
配信中枝を編集できる削除できる
paused
一時停止。配信は止まるが、それまでのデータは残る。再開できる。
配信中枝を編集できる削除できる
completed
終了。この状態からは二度と戻せない。結果レポートは引き続き読める。
配信中枝を編集できる削除できる

遷移できる向きは決まっている（商品や注文と違い、ここは厳密に検査される）。

  • 下書き → 開始する（running）
  • 配信中 → 一時停止（paused）／ 終了する（completed）
  • 一時停止 → 再開する（running）／ 終了する（completed）
  • 終了 → どこにも移せない
終了から戻せない理由

中断を挟んで再開すると、季節性や他のキャンペーンといった外部要因が異なる期間のデータが 1 つの実験に混ざり、結果を正しく読めなくなるため。「終了する」は不可逆な操作だと理解して押すこと。

6.3実験を作る

  1. 試したいことを 1 文の仮説にする（例:「レビューと Q&A を先に見せた方が、購入まで進む人が増えるのではないか」）
  2. 始める前に、必要な期間と曝露数を決めておく（6.6 の警告を参照）。ここを決めずに始めると結果を読めない
  3. /admin/experiments の「新規作成」を押す
  4. 実験キーに pdp_section_order または pdp_cta_copy を入れる。既存のキーは使えないので、同じ場所を再度試すなら pdp_section_order_v2 のような別名にする——ただしその名前ではフロントが読まないため画面は変わらない。重要 現状、同じ場所で 2 回目の実験を回すことはできない（6.7）
  5. 実験名と仮説を書き、対象にする訪問者の割合（％）と主要指標を決める
  6. 枝を 2 つ以上作る。対照群はちょうど 1 つ選ぶ。片方の設定値（config）は空のまま＝現行の挙動、もう片方に変更後の JSON を書く、という組み方が読みやすい
  7. 「下書きとして作成」を押す。この時点ではまだ誰にも配信されない
  8. 一覧で内容を確認する。間違いがあれば削除して作り直す（下書きのうちなら削除できる。ただし削除ボタンが管理画面に無いため、実際には 08 章の手順が必要）

6.4作成フォームの項目

項目意味と制約
実験キーコードから参照される識別子。1〜64 文字、全実験で一意。後から変更できない
実験名一覧に出る表示名。1〜128 文字
仮説任意。結果を読むときの前提になるので、必ず書いておく
対象にする訪問者の割合1〜100（％）。100 なら全員が実験に入る
主要指標成果として数えるイベント名。既定は purchase。候補（purchase / add_to_cart / begin_checkout / click / impression）が出るが自由入力なので、打ち間違えると成果が 0 のまま集計される
枝（バリアント）2〜6 個。それぞれ キー / 表示名 / 重み / 対照群かどうか / 設定値（JSON）を持つ
└ 重み（weight）0〜1000 の整数。合計が 100 である必要はない（比率として使われる。50:50 も 1:1 も同じ）
└ 対照群ラジオボタンでちょうど 1 つ。リフト（改善率）を測る基準になる
└ 設定値（config）JSON をそのまま手入力する。オブジェクト以外（配列・数値・文字列）は保存時に弾かれる。書き方は 6.1 の表

6.5開始する・監視する

  1. 一覧の「開始する」を押す。押した瞬間から配信が始まり、開始日時が記録される
  2. 店頭で自分の目でも確認する。ブラウザのシークレットウィンドウで開くと別の訪問者として扱われるので、両方の枝を見比べられる
  3. 実験名または「結果」から結果レポートを開き、まず SRM 警告が出ていないかを見る（6.6）
  4. あらかじめ決めた期間・曝露数に達するまで待つ。途中で結果を見て止めない
割り当てのしくみ（知っておくと問い合わせに答えられる）

どの枝に入るかは、端末ごとの匿名 ID から毎回計算される。同じ端末なら常に同じ枝になる（ログインの有無に関わらず）。さらに一度でも実際に画面を見た訪問者は、その時の枝が記録され、以後はそちらが優先される。
曝露が記録されるのは対象の画面が実際に描画された瞬間で、ページを開いただけでは記録されない。したがって「対象 100％」でも、商品ページを見ていない人は曝露に数えられない。

6.6結果を読む

結果レポートは上から ①SRM 警告 → ②枝ごとの成果 → ③ファネル の順に並んでいる。この順で読む。

① SRM 警告（出ていたら他は読まない）

設計した配分（重み）と、実際に曝露した人数の比がずれていないかの検定。赤い警告が出ていたら、割り当てか計測に不具合がある可能性が高い。この場合 CVR の差は信用せず、原因を特定してから実験をやり直す。

  • 警告が出るのは、ずれが偶然では説明しづらい水準（p < 0.001）のときだけ。通常より厳しくして誤警告を減らしている
  • 総曝露が 20 未満のときは判定しない（データが少なすぎて検定が成り立たないため）。「警告が出ていない＝正常」とは言えない期間がある

② 枝ごとの成果

列意味
曝露その枝の画面を実際に見た訪問者の人数（イベント数ではない）。すべての率の分母になる
成果主要指標のイベントを1 回以上起こした訪問者の人数。曝露した時刻より後のイベントだけを数える
達成率成果 ÷ 曝露。いわゆる CVR
リフト（95% 信頼区間）対照群に対する達成率の改善率（％）。区間が 0 をまたいでいるうちは「差があるとは言えない」。有意なときだけ色が付く
p値対照群との差が偶然で起きる確率の目安。0.05 未満で「有意」として扱う。データが足りないときは「—」になる
指標値の合計イベントに付いた数値の合計。購入なら売上金額にあたる
1人あたり指標値の合計 ÷ 曝露。購入なら訪問者 1 人あたりの売上
「有意になったら止める」をやらない

p 値が 0.05 を下回っても、それは「偶然ではなさそう」を意味するだけで、採用の可否を決めるものではない。毎日結果を覗いて有意になった時点で止めると、本当は差が無い変更でも高い確率で有意に見えてしまう。開始前に必要な曝露数と期間を決め、そこまで回してから読むこと（結果画面にも同じ注意書きが出ている）。

③ ファネル

ページ閲覧 → 商品ページ閲覧 → カート投入 → カート閲覧 → 注文手続き開始 → 購入 の 6 段について、各段に到達した人数と、曝露に対する到達率を並べる。どこで人が減っているかの見当をつけるために使う。

ファネルは簡易版

各段に到達した人数を並べているだけで、その順序どおりに通過したかは見ていない。前の段より後の段の人数が多くなることもありうる。厳密な経路分析には使えない。

6.7終わらせる・やり直す

  1. あらかじめ決めた期間・曝露数に達したら結果を読む
  2. 採用する枝を決めたら、一覧の「終了する」を押す。終了日時が記録され、配信が止まる
  3. 勝った枝の内容を実際の画面に反映する作業は、実験機能の外で行う。実験を終了しても店頭は自動的に勝者の見た目にはならず、全員が既定（＝対照群と同じ）の画面に戻る
配信を始めたあとに枝の内容は直せない

枝のキー・表示名・重み・設定値（JSON）を変更できるのは下書きのときだけである。配信を始めてから「並び順を少し変えたい」となった場合、その実験を終了させて、別のキーで作り直すしかない。
しかし画面が変わるキーは pdp_section_order と pdp_cta_copy の 2 つだけで、キーは全実験で一意である。したがって同じ場所で 2 回目の実験を行うことは、現状できない（1 回目の実験レコードを消す必要があるが、配信済みの実験は削除できない）。実験を始める前に、設定値を店頭で必ず目視確認すること。

6.8やってはいけない操作

配信中の重み（weight）を変えない

枝の割り当ては重みから計算されるため、途中で重みを変えると割り当ての境界が動き、配分が設計とずれる。すでに曝露した人は元の枝のままなので、新しく入る人だけが別の比率で割り振られ、結果として SRM 警告の原因になる。
管理画面には編集フォームが無いので通常は起こらないが、API を直接叩けば変更できてしまう。配分を変えたいときは下書きのうちに行うこと。

配信済みの実験を消さない

一度でも配信した実験は「終了」にする。削除できるのは下書きだけであり、これは意図的な制約である（曝露と成果の記録が孤立するのを防ぐため）。
