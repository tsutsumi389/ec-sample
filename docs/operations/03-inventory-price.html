03在庫と価格

在庫にも価格にも専用の画面は無い。どちらも商品編集モーダルの 1 項目として、直接書き換える。

3.1在庫が動く 3 つの経路

きっかけ動き誰が
注文が確定した注文された数だけ減る購入者（自動）
購入者が自分で注文をキャンセルしたその注文の数量が戻る購入者（自動）
商品編集フォームで在庫数を保存した入力した数値で上書きされる運営担当（手動）
カートに入っている数量は在庫を押さえない

在庫が引き当てられるのは注文が確定した瞬間の 1 回だけである。何人がカートに入れていようと在庫は減らず、先に注文を確定した人が取る。カートに残ったまま在庫が尽きた商品は、注文確定の時点で「在庫が不足しています」と弾かれる。

管理画面からのキャンセルでは在庫が戻らない

注文管理でステータスを「キャンセル」に変えても、在庫は 1 つも戻らない。戻るのは購入者本人がマイページからキャンセルしたときだけである。運営側でキャンセルしたら、続けて商品編集で在庫を手で足す必要がある（手順は 04 章）。

3.2在庫数を直す

  1. /admin/products で対象商品の「編集」を押す
  2. 「在庫数」の欄を、入荷後のあるべき総数に書き換える（増減の入力欄ではない。10 個入荷したなら現在値 3 に対して 13 と打つ）
  3. 「保存する」を押す。一覧の在庫列が変わったことを確認する
在庫の更新は「その瞬間の値で上書き」される

モーダルを開いてから保存するまでの間に注文が入っていた場合、その注文で減った分は保存によって取り消される（モーダルが開いた時点の古い値を書き戻すため）。
在庫を直すときは、開いたらすぐ保存すること。モーダルを開いたまま長時間放置しない。心配なときは保存後に一覧の在庫列を見て、想定と合っているかを確認する。

在庫まわりで用意されていないもの

在庫調整の専用画面、入荷登録、増減の履歴、在庫が少ない商品の絞り込み、閾値を割ったときの通知——いずれも存在しない。在庫の把握は管理画面の外（実際の倉庫や台帳）で行い、その結果をこのフォームに書き写すという運用になる。

3.3在庫の少なさが店頭に出る条件

在庫数店頭の表示
0「在庫切れ」バッジ。図版が薄くなり、カートに追加ボタンが押せなくなる（文言も「在庫切れ」）。一覧からは消えない
1〜5「残り N 点」。買い急ぎを促す表示
6 以上「在庫 N 点」。ふつうの表記
これらが出るのは「公開中」の商品だけ

「在庫切れ」も「残り N 点」も、販売状態が on_sale のときにしか表示されない。一時停止中の商品は在庫が 0 でも「販売停止中」としか出ない。つまり在庫の状況を店頭で伝えたいなら、公開中のままにしておく必要がある。

3.4欠品したときの選択

在庫が 0 になっても商品は自動では止まらない。どう見せるかは運営が選ぶ。

方針操作店頭の見え方
すぐ再入荷する何もしない（公開中のまま）一覧に残り「在庫切れ」バッジ。ページは開けるが買えない。入荷したら在庫数を打ち直すだけで復帰する
再入荷の目処が立たない販売状態を「一時停止」に一覧に残るが「販売停止中」。在庫切れであることは伝わらなくなる
もう仕入れない販売状態を「販売終了」に一覧から消える。URL を知っている人だけがページを見られる

3.5価格の考え方

セール価格なし
¥12,800
定価がそのまま実売価格になる
セール価格あり
¥12,800 ¥9,80023%OFF
セール価格が実売価格になり、定価に打ち消し線が付く

入力する価格は 2 つだけ。

  • 価格（定価）— 常に必須。セール中は打ち消し線付きで並記される
  • セール価格（任意）— 入っていればこちらが実売価格になる。空にすれば定価に戻る

カートの小計も、注文金額も、クーポンの最低注文金額の判定も、すべて実売価格で計算される。

3.6セールを始める・終える

  1. 対象商品の「編集」を開き、「セール価格（円）」に売価を入れて保存する。保存した瞬間からセールが始まる
  2. 店頭で、打ち消し線付きの定価と割引率バッジが出ていることを確認する
  3. セールを終えるときは、同じ欄を空にして保存する。これで定価に戻る
セールは自動では終わらない

開始日時・終了日時を持つ項目が無い。始めるのも終わらせるのも手作業で、消し忘れればセール価格のまま売れ続ける。複数商品をまとめてセールにする手段も無いため、1 商品ずつ編集モーダルを開いて入力する。終了予定は管理画面の外（カレンダー等）で管理し、当日に手で戻すこと。

定価より高いセール価格が、警告なしで通る

セール価格には「定価以下」の制限が無い。定価 10,000 円の商品にセール価格 12,000 円を入れて保存すると、実売価格は 12,000 円になる。しかもセール表示の判定は「セール価格が定価より安いこと」なので、打ち消し線も割引率バッジも出ない——店頭にも管理画面にも異常の手掛かりが一切出ないまま、高い方の値段で売れる。桁を間違えたときに最も危険なのがこの欄である。
同様に 0 も通る（＝ 0 円で売れる）。保存後は必ず店頭の価格表示を目視すること。

価格を変えても過去の注文は変わらない

注文明細は注文時点の商品名と価格を写し取って保持している。後から価格を直しても過去の注文金額が動くことはないので、価格改定を過去の売上を気にせず行える。
ただし逆に、変更前の価格を管理画面から知る方法は無い（価格の履歴が残らない）。元に戻す可能性がある変更は、変更前の値を手元に控えてから行うこと。
