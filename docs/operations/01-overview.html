01運用の全体像

運用に入る前に押さえておく前提——誰が何をできるのか、管理画面はどこまでを担っているのか、そして全画面に共通する作法。

1.1運用の入口

  1. make up-d でコンテナを起動する（初回は make fonts と make secret が自動で走り、DB のマイグレーションとシード投入も起動時に完了する）
  2. ブラウザで http://localhost:3000 を開き、管理者アカウントでログインする
  3. ヘッダーに「管理画面」リンクが出る。これは ログイン中のユーザーが管理者のときだけ表示される
  4. http://localhost:3000/admin が運用の起点。以降の作業はすべてこの配下で行う
用途アカウント備考
admin@example.com / admin123管理者シードで作られる唯一の管理者。管理画面に入れるのはこのアカウントだけ
user@example.com / user123一般ユーザー店頭側の確認用。管理画面を開こうとするとトップページへ戻される
管理者を増やす画面は無い

会員登録も、プロフィール更新も、権限は user で固定されている。ユーザー管理画面にも権限を変えるボタンは無い。2 人目の管理者を作る手段は DB を直接書き換えることだけである（手順は 08 章）。

1.2登場人物

運営担当（admin）

本書の主語。商品・カテゴリ・クーポン・注文・A/Bテストを管理画面から操作する。権限は 1 種類しかないため、担当を分けても全員が全部を触れる。

購入者（user）

店頭側の利用者。商品を買い、レビューを書き、商品に質問し、自分の注文を自分でキャンセルできる（在庫が戻るのはこの経路だけ）。

訪問者（未ログイン）

端末ごとの匿名 ID で識別される。カートは端末側に持ち、A/Bテストの割り当てと計測もこの ID で行われる。会員登録時にカートはサーバーへ引き継がれる。

AI（人手を介さず動く部分）

商品 Q&A の回答、ホームのおすすめ、店員アシスタントの応答、検索用の埋め込み。いずれも人間の承認を挟まず即座に公開される（詳細は 07 章）。

1.4全画面に共通する作法

  1. 一覧は常に全件。商品・注文・ユーザー・カテゴリ・クーポンのどの一覧にも、検索・絞り込み・並べ替え・ページングが無い。商品一覧は登録順（ID 昇順）、注文一覧は新しい順で固定される
  2. 保存と状態変更は即時に確定する。取り消し（undo）は無い。特に注文のステータスはプルダウンを選んだ瞬間に反映される（確認ダイアログも無い）
  3. 変更履歴が残らない。誰がいつ何を変えたかを記録するテーブルも画面も無い。価格を戻したいときに「前がいくらだったか」は分からない
  4. 確認ダイアログがあるのは削除系だけ。商品・カテゴリ・クーポンの削除でブラウザ標準の確認が出る。それ以外の操作は無言で通る
  5. エラーはその場に赤字で出る。ただし想定されていないサーバー側の失敗はすべて「サーバーエラーが発生しました。しばらくしてから再度お試しください。」に丸められ、原因は画面から分からない（make logs-backend で確認する）
  6. 店頭には反映済み・管理画面には未反映というズレが起きうる。カテゴリの選択肢はブラウザのタブ内に保持されるため、別タブで開きっぱなしの管理画面には新しいカテゴリが出ない。再読み込みで解消する

1.5できること・できないこと（総覧）

各章で詳述する内容の索引。「できないこと」は、その作業を 08 章の手順（DB 直操作・API 直叩き）に回すか、運用でカバーする必要があることを意味する。

領域管理画面でできることできないこと
商品 登録・全項目の編集・販売状態の変更・アーカイブ（＝「削除」ボタン） 物理削除、一括登録（CSV）、SKU やカテゴリでの検索、画像のアップロード、画像・仕様の並べ替え
在庫 商品編集フォームで在庫数を直接書き換える 増減入力（＋10 など）、入荷登録、在庫履歴、在庫少の商品を絞り込むこと
価格 定価とセール価格の書き換え セール期間の指定と自動終了、価格改定の予約、値引き率の上限管理、価格履歴
カテゴリ 作成・改名・削除（削除しても商品は「未分類」に残る） 階層化、並び順の指定、所属商品の一括付け替え
注文 一覧の閲覧とステータスの変更 明細・配送先・割引額の確認、注文詳細ページ、検索・絞り込み、CSV 出力、伝票発行、追跡番号の登録、顧客へのメール通知
クーポン 発行・編集・有効/無効の切り替え・削除 使用回数の制限、1 人 1 回の制限、対象商品やカテゴリの限定、使用実績の確認
A/Bテスト 作成（下書き）・開始・一時停止・再開・終了・結果レポートの閲覧 作成後の内容編集、削除、配信開始後の枝（バリアント）の修正
レビュー —（管理画面に画面が無い） 閲覧・削除・非表示・返信のすべて
商品 Q&A —（管理画面に画面が無い） AI が書いた回答の確認・修正・削除、人手での回答
ユーザー 一覧の閲覧（ID・名前・メール・権限の 4 列） 権限変更、退会・凍結、パスワードリセット、注文履歴へのドリルダウン、検索
検索・レコメンド —（商品保存時に自動で更新される） 全件の再構築を管理画面から実行すること（API は存在するが導線が無い）
分析 A/Bテストの結果レポート（曝露・成果・リフト・ファネル） 実験に紐づかない売上・CVR・アクセスの集計、生の行動ログの閲覧、AI アシスタントの会話ログの閲覧
